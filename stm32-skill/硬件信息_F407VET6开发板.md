# STM32F407VET6 开发板硬件信息（原理图梳理）

> 来源：用户提供的《STM32F407VET6原理图.pdf》。以下引脚均已对照原理图网络标号逐一确认。
> 用途：作为 stm32-keil skill 开发的硬件事实依据，未实测项已标注。
> 端口号与工具安装路径因机器而异，请以脚本探测结果为准。

## 一、主控与资源

| 项目 | 参数 |
|------|------|
| 主控 | STM32F407VET6 |
| 内核/主频 | Cortex-M4F（带 FPU），168 MHz |
| Flash | 512 KB |
| SRAM | 192 KB（含 64 KB CCM） |
| 封装 | LQFP100，82 个 IO |
| 外设 | 以太网、FSMC、3×ADC、多路 SPI/I2C/UART、2×DAC、DMA 等 |
| 与 F407VGT6 区别 | 仅 Flash 容量（VGT6 为 1MB），引脚一一对应可互换 |

## 二、电源与时钟

- **供电**：TypeC 接口 USB5V → 500mA 自恢复保险丝 FU1 → SPX1117M3-3.3 LDO（U1）→ 3V3
- **VDDA**：经 0Ω 电阻 R8 接 3V3
- **HSE 外部高速晶振**：Y2 = **8 MHz**（接 PH0/OSC_IN、PH1/OSC_OUT，负载电容 20P）
- **LSE 外部低速晶振**：Y1 = 32.768 kHz（接 PC14、PC15，负载电容 10P）
- **RTC**：CR2032 纽扣电池座（BAT54C 切换，接 VBAT）

## 三、启动与复位

- **BOOT0**（引脚94）：经 R7 = 10K 下拉到 GND（默认主 Flash 启动）；同时引出到 SWD 接口 P1 第 1 针（网络标号 104），下载器可拉 BOOT0
- **BOOT1 = PB2**（引脚37）：经 R6 = 10K 下拉到 GND
- **启动模式**：
  - BOOT0=0：主 Flash 启动（正常运行）
  - BOOT0=1：系统存储器启动（ISP 串口 / DFU 烧录）
  - BOOT1=1：内置 SRAM 启动（调试临时代码）
- **复位按键 S2**：接 NRST（引脚14），按下拉低复位，C5 滤波

## 四、SWD 下载接口 P1（5 针）

| 针脚 | 信号 | MCU 引脚 |
|------|------|----------|
| 1 | BOOT0 | BOOT0 |
| 2 | 3V3 | — |
| 3 | GND | — |
| 4 | SWDIO | PA13 |
| 5 | SWCLK | PA14 |

> 仅 SWD，无 JTAG 专用接口。

## 五、板载 LED 与按键

### LED
- **D1：电源指示灯**（非 MCU 控制）。3V3 → R1(1K) → D1 阳极，阴极 → GND，上电常亮
- **D2：用户 LED**。3V3 → R5(1K) → D2 阳极，阴极 → **PA1**
  - **低电平点亮**（PA1 输出 0 亮，输出 1 灭）

### 用户按键 S1
- 3V3 → R2(1K) 上拉 → S1 → **PA0**（WKUP 引脚）
- **按下为低电平，松开为高电平**（外部已上拉，GPIO 配置可不再上拉）

## 六、USB（TypeC，USB OTG FS）

- D+（UD+）→ **PA12**（经 0Ω R4）
- D-（UD-）→ **PA11**（经 0Ω R3）
- VBUS → USB5V（供电）
- **本板没有 USB 转串口（USB-TTL）芯片**，TypeC 直连 MCU 的 USB OTG FS。
  - 不能直接用该口做 UART 串口；可用方向：
    1. USB CDC 虚拟串口（固件实现）
    2. USART1（PA9/PA10）外接 USB-TTL 模块
    3. 调试器 VCP / J-Link RTT

## 七、W25QXX SPI Flash（U2）

| Flash 引脚 | 网络标号 | MCU 引脚 |
|------------|----------|----------|
| CS (1) | F_CS | **PA15** |
| SO/MISO (2) | SPI1_MISO | **PB4** |
| WP (3) | — | 3V3（常使能） |
| GND (4) | — | GND |
| SI/MOSI (5) | SPI1_MOSI | **PB5** |
| SCLK (6) | SPI1_SCLK | **PB3** |
| HOLD (7) | — | VCC（3V3） |
| VCC (8) | — | 3V3 |

> **关键坑**：PB3/PB4/PA15 默认为 JTAG 引脚（JTDO/JNTRST/JTDI）。
> 用作 SPI1（重映射复用 AF5）+ 普通 GPIO 后，**JTAG 调试不可用，只能用 SWD（PA13/PA14）**。
> J-Link / ST-Link 必须配置为 **SWD 模式**，不能用 JTAG 模式连接。

## 九、TFT 显示屏接口 P2（8 针，SPI 屏）

| 针脚 | MCU 引脚 | 推测功能（待屏资料确认） |
|------|----------|--------------------------|
| 1 | 3V3 | 电源 |

## 十、IO 扩展口

- P3、P4 各为 23×2 双排针（Header 23X2），引出 3V3、5V、GND 及全部空闲 IO
- 外接模块/传感器时从这两组排针取信号

## 十一、串口验证方案（重要，影响例程设计）

由于板载 TypeC 无 USB-TTL 芯片，UART 例程验证有三种路径：

1. **USART1 外接 USB-TTL**：PA9(TX)/PA10(RX)，115200 8N1 —— 需用户有 USB-TTL 模块
2. **USB CDC 虚拟串口**：用 PA11/PA12（TypeC），电脑枚举为 COM 口，无需额外模块
3. **J-Link RTT**：调试器通道打印，不占用串口（适合调试，不适合验证 UART 外设本身）

> uart_echo 例程建议：USART1 版本（验证 UART 外设）+ USB CDC 版本（免模块）按需提供。

## 十三、参考工程分析（严格只读，本地私有资产）

> 用户正在使用，**禁止任何修改**，仅作 check/build 脚本的样本参考。

**工程性质**：STM32CubeMX 生成的标准 Keil MDK 工程（含 STM32F407.ioc）。

**外接模块接线（IO 扩展口，参考工程实际使用）**：

| 模块 | 引脚 | 说明 |
|------|------|------|
| RGB-R | PA0（RED_Pin） | 高电平点亮 |
| RGB-G | PA1（GREEN_Pin） | 高电平点亮（与板载 D2 复用引脚） |
| RGB-B | PA2（BLUE_Pin） | 高电平点亮 |
| 无源蜂鸣器 | PA3（BUZZER_Pin） | TIM2 中断翻转，3kHz 方波 |
| TFT-LCD | PB13/PB15(模拟SCL/SDA)、PB12(CS)、PB14(RST)、PC5(RS)、PB1(BLK) | 即原理图 P2 接口 |
| I2C1（预留） | PB6(SCL)/PB7(SDA) | CubeMX 配置，100kHz |

**功能**：串口（USART1 PA9/PA10，115200 8N1，中断单字节接收）接收 R/G/Y 命令 → 切换 RGB 灯 + 蜂鸣器 + TFT 显示，回发 "RED ON" 等确认。

**时钟（参考工程实际配置，重要）**：
- 使用 **HSI 内部 16MHz RC**，PLL 关闭（RCC_OSCILLATORTYPE_HSI，SYSCLKSOURCE_HSI）
- SYSCLK=16MHz，AHB=16MHz，APB1=4MHz（DIV4），APB2=8MHz（DIV2），FLASH_LATENCY_0
- **没有使用 8MHz HSE，也没有 PLL 倍频到 168MHz**
- TIM2 挂 APB1，定时器时钟 = APB1×2 = 8MHz（与代码注释一致）
- skill 自己的例程默认应配 HSE 8MHz + PLL → 168MHz（发挥芯片性能），但要知道参考工程是 HSI 16MHz

**上电串口输出**：`LED Control Ready! Send R/G/Y`（USART1，可用于实测 J-Link CDC 通路）。

## 十四、实测结论（2026-09-28）

### SWD 烧录通道：✅ 完全正常
- J-Link OB 固件：`J-Link OB-STM32F072-128KB-CortexM`，硬件 V1.00
- VTref = 3.300V，SWD 4000 kHz，SW-DP ID 0x2BA01477
- CPUID 0x410FC241 → Cortex-M4 r0p1，芯片识别正确
- 只读连接全程未 halt 目标（参考工程持续运行未受干扰）；末尾 "CPU is not halted" 是对运行中的芯片执行 g 的正常提示，非故障

### SWD 速度：⚠️ 500 kHz 才稳定（2026-09-28 烧录实测）
- **1000 / 4000 kHz 时，erase/loadfile 报 `Verification of RAMCode failed @ 0x20000000` / `Failed to download RAMCode`**，无法擦除烧录
- 降到 **500 kHz** 后 erase + loadfile 稳定成功（已固化为 stm32_flash.py 默认 --speed）
- SRAM 硬件正常：halt 下手动 w4 写 0x20000000 / 0x20010000 / CCM 0x2001C000 均正确读回；故 RAMCode 失败是高速 SWD 时序/信号问题，非 SRAM 损坏
- 高速连接还间歇出现 "CPU seems to be kept in reset forever"、halt 失败、PC 读到 Flash 字符串字节（如 0x412F6F72）；降速 / 重新插拔可恢复

### RGY 流水灯 rgy_flow：✅ 实机验证（2026-09-28）
- 外接 RGY 灯：R=PA0 / Y=PA1 / G=PA3，高电平点亮；时钟 HSI 16MHz
- 程序运行时读 GPIOA->ODR（0x40020014），低位循环 `0x01(R)→0x02(Y)→0x08(G)`，同一时刻只亮一个，流水效果成立
- 注：板载 D2 网络也在 PA1（低电平点亮），与外接 Y 共用，不影响逻辑

### J-Link CDC 串口：✅ 实测通过
- 监听 J-Link CDC 串口 @115200 + 按复位，成功收到 `LED Control Ready! Send R/G/Y`（USART1 上电字符串）
- 确认 J-Link OB 的 CDC TX/RX 已物理连接到目标 USART1（PA9/PA10），该口可直接用于烧录调试时的串口收发
- 首次监听未收到是因为未触发复位（复位后约 1.5s 蜂鸣器响完才发字符串）

### 串口验证方案（最终建议）
鉴于无 USB-TTL、J-Link CDC 疑似未接线、TypeC 已接 USB OTG FS：
1. **首选 USB CDC 虚拟串口**：用 PA11/PA12（TypeC 口），固件实现 USB CDC，电脑枚举新 COM 口，免额外硬件，同时该口供电
2. **辅助 J-Link RTT**：走已验证的 SWD 通道打印，免接线，适合调试（写入 debugging.md）
3. USART1 版本例程仍提供（验证 UART 外设），但实机验证需用户补接 CDC TX/RX 或 USB-TTL
